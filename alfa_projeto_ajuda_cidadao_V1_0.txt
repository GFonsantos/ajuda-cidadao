1. A ALMA DO PROJETO
--------------------------------------------------------------------------------

NOME: Ajuda Cidadão.
PROPÓSITO: Biblioteca aberta de modelos, minutas e orientação em linguagem simples.

O QUE É: um projeto acadêmico de extensão universitária focado em inclusão 
digital e acesso à justiça. O site permite que qualquer cidadão, mesmo leigo 
juridicamente, encontre, preencha e imprima documentos formais (requerimentos, 
ofícios, contestações) sem intermediários e sem "juridiquês".

PRINCÍPIOS INEGOCIÁVEIS:
  1. PRIVACY-BY-DESIGN — Zero banco de dados, zero login, zero coleta de dados. 
     Os dados preenchidos pelo usuário NUNCA saem do aparelho dele (client-side).
  2. LINGUAGEM SIMPLES — Foco no cidadão vulnerável. O site explica "para que 
     serve", "quem tem direito" e "onde entregar" antes de mostrar o documento.
  3. ARQUITETURA LEVE (Jamstack) — HTML, CSS puro, JS Vanilla e um arquivo JSON 
     estático. Carregamento ultrarrápido em 3G e hospedagem gratuita (GitHub Pages).
  4. ACESSIBILIDADE UNIVERSAL — Botões A+/A-, Alto Contraste, navegação por 
     teclado e compatibilidade com leitores de tela (WCAG 2.1).
  5. ESCALABILIDADE — O site foi desenhado para crescer. Adicionar novos 
     documentos no futuro não exige programar novas telas, apenas alimentar o JSON.

VISÃO DE FUTURO: Tornar-se um site de uso real e usual na sociedade, 
especialmente para Pequenas Causas (Juizados Especiais).

5. MODELO DE DADOS (acervo-minutas.json)
--------------------------------------------------------------------------------

O arquivo JSON é o cérebro do conteúdo. Cada objeto "minuta" contém:
  - id: identificador único para a URL (ex: saude-medicamento-sus)
  - categoria: nome exato da categoria (usado nos filtros)
  - titulo: título do documento
  - resumo: explicação curta em linguagem simples
  - onde_entregar: local físico ou digital para protocolar
  - documentos_anexos: array de strings com documentos necessários
  - texto_minuta: O texto jurídico completo. Os campos a serem preenchidos
    DEVEM estar entre colchetes, ex: [SEU NOME COMPLETO].

REGRA DE OURO DO MOTOR: Qualquer texto entre colchetes no JSON será 
automaticamente transformado em um input no formulário (documento.js).


--------------------------------------------------------------------------------
6. FLUXOS VITAIS (Como a mágica acontece)
--------------------------------------------------------------------------------

FLUXO DE BUSCA E CATÁLOGO:
  O usuário digita na Home -> home.js redireciona para biblioteca.html?q=termo.
  biblioteca.js faz fetch() no JSON, filtra os dados (incluindo o termo da URL)
  e renderiza os cards na tela.

FLUXO DE PREENCHIMENTO (documento.html):
  1. documento.js lê o ID na URL (?id=...).
  2. Busca no JSON e joga o texto no lado direito da tela.
  3. Usa Regex /\[(.*?)\]/g para encontrar os colchetes.
  4. Cria um input para cada colchete único encontrado.
  5. Ao digitar, o script varre o texto novamente e substitui os colchetes
     pelo que foi digitado (atualização em tempo real).

FLUXO DE MÁSCARAS (mascaras.js):
  O documento.js verifica o nome do campo. Se tiver "CPF", aplica máscara de CPF. 
  Se tiver "NOME", aplica caixa alta. Se tiver "ENDEREÇO", aplica Title Case.

FLUXO DE IMPRESSÃO:
  A classe .folha-a4 tem as medidas de uma folha. No CSS @media print, o site 
  esconde tudo com a classe .no-print (header, botões, formulário) e transforma 
  o layout em uma via única, deixando apenas o texto do documento visível.

7. REGRAS DA CASA (pactuadas com o dono — não quebre)
--------------------------------------------------------------------------------

  R1. Separação Total: Cada página tem seu CSS e JS próprio. Não misture regras 
      de home.css com documento.css.
  R2. Formato de Entrega: O assistente deve entregar blocos completos de código 
      (copiar-colar) para arquivos novos, ou usar "Procure por X / Substitua por Y" 
      para ajustes em arquivos existentes.
  R3. Documentação: Todo arquivo novo deve ter o cabeçalho em bloco de comentário 
      explicando (O que faz / Depende de / Mexe em).
  R4. Zero Coleta: NUNCA adicione scripts de analytics, cookies de rastreamento 
      ou APIs que enviem dados do formulário para fora.
  R5. Acessibilidade: Todo elemento interativo novo precisa de aria-label, foco 
      visível e contraste adequado.
  R6. Visual: Não usar emojis na interface (exceto onde já foi pactuado). Prezar 
      por ícones, cards limpos e tipografia nativa.
  R7. Organização: Manter as pastas e a arquitetura de arquivos conforme a seção 4.


--------------------------------------------------------------------------------
8. DECISÕES DE ENGENHARIA E SEUS PORQUÊS
--------------------------------------------------------------------------------

  D1. Por que sem Banco de Dados? Para garantir privacidade total (LGPD) e 
      custo zero de hospedagem. O formulário roda no navegador.
  D2. Por que gerar o formulário dinamicamente? Para escalar. Se o usuário 
      adicionar 50 minutas no JSON, o código JavaScript já cria os formulários 
      de todas elas sem precisar escrever 50 HTMLs diferentes.
  D3. Por que impressão via CSS @media print? O usuário não precisa de Word ou 
      Adobe. Ele preenche no celular e salva como PDF direto pelo navegador.
  D4. Por que o arquivo de máscaras é separado? Para que o motor de formulário 
      fique limpo e as regras de formatação fiquem centralizadas num só lugar.
  D5. Por que system-ui como fonte? Para o site carregar instantaneamente em 
      conexões 3G ou em computadores antigos da faculdade, sem depender do 
      Google Fonts.


--------------------------------------------------------------------------------
9. DÍVIDAS TÉCNICAS E ARMADILHAS CONHECIDAS
--------------------------------------------------------------------------------

  - CORS: A página documento.html usa fetch() para ler o JSON. Abrir o HTML 
    com duplo clique NÃO FUNCIONA. Precisa do Live Server (localhost) ou 
    de um servidor estático (GitHub Pages).
  - Cache: Se as alterações de CSS/JS não aparecerem, usar Ctrl+Shift+R no 
    navegador para limpar o cache.
  - Backspace em inputs com máscara: Editar o meio de um CPF pode fazer o 
    cursor pular para o final. (Funcional, mas pode ser refinado no futuro).
  - Acervo Inicial: O JSON tem 8 minutas. Ainda faltam documentos de Pequenas 
    Causas (Ação de Cobrança, Dano Moral, etc.) e contratos.
